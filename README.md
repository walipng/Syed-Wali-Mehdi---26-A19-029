# UAS-DTU Round 2 Task: Casualty Analysis using a Rover Guided by a UAV

## Project Overview
This project implements a solution for the UAS-DTU Round 2 Software Task. The objective is to simulate a rover deployed in a triage scenario, guided by a segmentation map generated by a UAV. The rover must navigate traversable terrain (avoiding obstacles), identify casualties (classified by age and severity using shapes and colors), calculate optimal paths to maximize the casualty score, and finally reach a designated safe zone.

## 5-Day Logbook: Learnings and Problems Encountered

### Day 1: Project Setup and Python Basics
**Learnings:**
* Set up the development environment, including Python 3.10 and necessary libraries.
* Brushed up on Python data structures (lists, dictionaries, tuples) which are crucial for storing casualty coordinates and calculating path sequences.
* Initialized the GitHub repository to track progress as per the evaluation criteria.

**Problems Encountered:**
* **Environment Setup:** Encountered minor path variable issues while setting up the virtual environment, which were resolved by properly configuring the system paths.
* **Understanding the Coordinate System:** Realized early on that image coordinates (x, y) in arrays can sometimes be confusing compared to standard Cartesian coordinates (row, column mappings in NumPy).

### Day 2: Image Processing with OpenCV & NumPy (Masking)
**Learnings:**
* Learned how to read and manipulate images using OpenCV (`cv2.imread`, `cv2.cvtColor`).
* Utilized NumPy for fast array manipulations to create the Traversable vs Non-Traversable masks.
* Explored HSV color spaces to successfully threshold the black obstacles (non-traversable) and the three distinct shades of green (traversable terrain).

**Problems Encountered:**
* **Color Thresholding:** Finding the exact HSV bounds for the light, moderately dark, and darkest green terrains took trial and error. Standard RGB filtering was too susceptible to noise, making HSV a much better choice.
* **Noise in Masks:** The generated masks initially had jagged edges. Learned to use morphological operations (dilation/erosion) to smooth the obstacle boundaries.

### Day 3: Casualty Detection & Feature Extraction
**Learnings:**
* Implemented contour detection (`cv2.findContours`) to locate the casualties, the starting point (orange triangle), and the final destination (purple triangle).
* Used contour approximation (`cv2.approxPolyDP`) to identify the shapes (Circle, Star, Square) which correspond to Children, Adults, and Senior Citizens respectively.
* Mapped contour colors to Severity Scores (Red=Critical, Yellow=Moderate, White=Safe).
* Extracted the elevation data by checking which shade of green the casualty's center coordinates were resting on.

**Problems Encountered:**
* **Shape Approximation:** The 'Star' shape was particularly difficult to classify because the number of vertices detected varied depending on the contour approximation accuracy parameter ($\epsilon$). I had to fine-tune the epsilon value to reliably distinguish stars from circles and squares.
* **Nested Contours:** Casualties placed near the boundaries of different terrain elevations sometimes confused the contour hierarchy.

### Day 4: Pathfinding Algorithm Implementation
**Learnings:**
* Researched and implemented a grid-based pathfinding algorithm (A* Search) to navigate from the start (orange triangle) to the end (purple triangle) while avoiding black regions.
* Adapted the cost function of the algorithm to account for different traversal speeds on different terrains:
  * Light green: 20 px/s
  * Moderately dark green: 15 px/s
  * Darkest green: 10 px/s
* Developed the scoring logic: `(Displacement from start / Distance travelled) * Priority Score`.

**Problems Encountered:**
* **Computational Complexity:** Running standard A* on a pixel-by-pixel basis for a large high-resolution image was incredibly slow. 
* **Optimization:** I had to downsample the grid for the pathfinding phase or implement a jump-point search to make the path calculation feasible within a reasonable time limit.
* **Traveling Salesperson Problem (TSP):** Deciding the optimal order to visit the casualties to maximize the Path Score while minimizing time is a variation of the TSP. I implemented a greedy approach to visit the highest-value casualties first.

### Day 5: Visualization, Scoring, and Bonus Task
**Learnings:**
* Used OpenCV drawing functions (`cv2.line`, `cv2.circle`, `cv2.putText`) to overlay the calculated path, highlight covered casualties, and visually map the rover's journey on the original image.
* Computed the final global rankings for multiple maps based on Total Path Score and Total Travel Time.
* **Bonus Task Exploration:** Attempted the dynamic receptive field problem (moving a white circle to a black circle with restricted visibility). Implemented the image cropping logic to create the $(width/4 	imes height/2)$ receptive field.

**Problems Encountered:**
* **Drawing Paths:** Ensuring the drawn path lines were clearly visible without obscuring the casualty markers required careful layering of the drawing commands.
* **Bonus Task Constraints:** Managing the state of the rover without global data was challenging. I had to implement a local memory map to keep track of walls the rover had already seen to avoid getting stuck in dead ends.

## Installation & How to Run
1. Clone this repository.
2. Install dependencies: `pip install numpy opencv-python matplotlib`
3. Place the input images in the `input_images/` directory.
4. Run the main script: `python main.py`
5. The output masks, visual paths, and ranking text files will be generated in the `outputs/` folder.
